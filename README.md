My Reflection

This lab helped me better understand how an AI can make decisions by looking ahead at possible outcomes instead of choosing moves randomly. The main goal was to implement a Tic-Tac-Toe player using the Minimax algorithm, where the AI evaluates future game states and selects the move that gives it the best possible outcome. X acts as the maximizing player because it wants a utility value of 1, while O acts as the minimizing player because it wants a utility value of -1. A tie has a utility value of 0.

One issue I had while completing the assignment was understanding how each required function connects to the Minimax algorithm. At first, functions such as player, actions, result, winner, terminal, and utility seemed separate, but Minimax depends on all of them working correctly. For example, if player(board) incorrectly determines whose turn it is, the AI may place the wrong symbol. If actions(board) includes occupied spaces, the algorithm could attempt illegal moves. Likewise, if terminal(board) or winner(board) does not correctly detect a completed game, Minimax may continue searching states that should no longer be explored.

Another challenge was making sure that result(board, action) did not modify the original board. Since Minimax explores many possible future moves, changing the original board directly can affect other branches of the search tree and lead to incorrect decisions. Creating a copy of the board before applying an action was important because each possible move needs its own independent successor state. This helped me understand the difference between changing an existing object and creating a new state for a search problem.

The recursive structure of Minimax was also difficult at first. I had to understand that the algorithm does not only evaluate the next move; it keeps calling itself until it reaches a terminal board. Once it reaches a win, loss, or tie, it returns the utility value. Then the values move back up through the recursive calls. X chooses the maximum value among its possible actions, while O chooses the minimum value. Seeing this process in execution made the concepts of maximizing, minimizing, terminal states, and utility values much clearer.

Testing the program was especially helpful. I needed to check horizontal, vertical, and diagonal wins, as well as tie boards and boards with only one legal action left. I also had to verify that the AI would block a winning move from the opponent and take a winning move when one was available. These tests showed that even a small mistake in winner detection or turn selection could make the Minimax AI appear incorrect.

For extra practice and fun, I also worked with an additional game, Maze Escape. Adding another game helped me understand AI and game-related terms in a more practical way. Although Maze Escape is different from Tic-Tac-Toe, it still involves representing a game state, identifying legal actions, checking whether a goal or terminal condition has been reached, and deciding how an agent should move through an environment. In Tic-Tac-Toe, the AI searches through possible future boards to choose the best move against an opponent. In Maze Escape, the player or agent must move through a grid while avoiding obstacles and trying to reach an exit. This made it easier to understand terms such as state, action, successor state, terminal state, utility, and search because I could see how they apply to more than one kind of game.

Overall, this lab strengthened my understanding of adversarial search and recursion. The most important lesson was that Minimax is not simply a method for choosing a move; it is a structured way to model competition between two players with opposite goals. Tic-Tac-Toe was a good example because the board is small enough to explore completely, but it still demonstrates how an AI can make optimal decisions. Working on an extra game also made the terminology and execution process easier to understand, since I could compare how game logic and search concepts are used in different situations.
